# Security boundaries

Oxide is a desktop app whose webview can call Rust commands that start processes, read and write files and talk to the network, on behalf of the user, and it runs whatever the user types into a terminal. The security review behind #479 found that every weakness was one of a few recurring classes. This ADR records the rules that close them, so review has something to check against and CI fails a change that reintroduces the ones a machine can see. Changing a rule below needs a line in this ADR.

## Rules

- **New IPC commands.** A command takes ids, not paths, wherever an id exists. Every string argument is validated in Core, not in the webview: length cap, character set, and for paths, canonicalisation inside a checkout through the one resolve function. A command that starts a process, writes outside a checkout or opens something outside the app says so in its doc comment and has a negative test for each argument. Capabilities (`crates/oxide-app/capabilities/default.json`) grant plugins nothing beyond what is listed today without a line in this ADR (`core:window:allow-is-maximized` is granted so the custom Windows titlebar can query maximized state to switch Maximize/Restore and unmount edge resize handles).
- **Errors.** No `unwrap`, `expect` or indexing on data from the webview, the network, files or child processes. Mutexes recover from poisoning, through `LockExt::lock_recover()` (implemented in `oxide_platform::sync`), never `if let Ok(guard) = m.lock()`. A result is never discarded with `let _ =` or `.ok();`: use `diag::best_effort` (logs) or `SenderExt::tell` (a closed channel is the normal end of a terminal or a window) from `oxide_platform::diag`, or return it with `?`. Errors shown to the user or logged pass through URL-credential redaction.
- **Processes.** Argument arrays only. A shell is used only for text the user typed as a command in a terminal. Positional values that can start with `-` come after `--`. `git` and `gh` go through the hardened builders (`GitCommand` in `git_command.rs`, the `gh` runner in `github.rs`). OS helpers are absolute paths and start through `oxide_platform::command::os_command` (with `resolved_command`); an executable Oxide already resolved (an installed tool, the login shell) starts through `resolved_command`. Output read from a child is bounded.
- **File system.** Reads and writes for the webview go through resolve: only regular files, with size caps before allocation. Oxide's own data is `0700` / `0600`. Anything downloaded is verified against a pinned hash before it is unpacked or executed. Custom JSON themes in `~/.oxide/themes/` (`list_themes`, `save_theme`, `delete_theme`, `open_themes_folder`) are `0700` / `0600`, take validated ASCII filename stems (`1..=64` chars `[A-Za-z0-9_-]`, not starting with `.` or `-`), reject symlinks and path traversal via canonicalization inside `~/.oxide/themes/`, cap payloads at 1 MiB, and keep built-in `oxide-dark` / `oxide-light` protected from deletion or overwrite via IPC.
- **Webview.** No HTML sinks beyond the two documented ones. No remote scripts, frames or anchors that navigate the app. CSP changes need a line in this ADR. `freezePrototype` is deliberately off: Monaco and the terminal assign `toString` on plain `{}` namespace objects at module start, which throws a TypeError once `Object.prototype` is frozen (reproduced in strict-mode Node; not tried in a WKWebView build). Turn it on only after proving the editor and terminal load in a real build.
- **Unsafe.** Every block has a `SAFETY` comment stating the invariant. Signals to a process group go through the guarded helper (`crates/oxide-platform/src/posix/signal.rs`; Windows ends a Job Object instead). `unsafe` and OS-only APIs live only in the platform layer (ADR-0018).
- **Automation.** What a machine enforces:
  - Workspace lints `clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` and `clippy::undocumented_unsafe_blocks` are `deny` (`clippy.toml` exempts `#[test]` functions and `#[cfg(test)]` modules; integration-test files under `tests/` need a file-level `#![allow(..., reason = ...)]` because their helpers are not test functions; every allow carries a reason and none may appear elsewhere in production code), run by `cargo clippy --locked --workspace --all-targets -- -D warnings`.
  - Workspace lints `clippy::let_underscore_must_use` and `clippy::unused_result_ok` are `deny`, and `clippy.toml` lists `disallowed-methods` for `Mutex::lock`, `RwLock::read`, `RwLock::write` and `std::process::Command::new`, each with the replacement in its `reason`. Only the modules that implement a replacement (`sync.rs`, `diag.rs` and `command.rs` in `oxide-platform`, the Git and `gh` builders) allow them, with a reason; integration tests carry the file-level allow they already need for `unwrap`.
  - ESLint bans importing `@tauri-apps/api/core` and `@tauri-apps/api/event` outside `web/src/shared/ipc.ts` (typed `commands.*` come from `bindings.ts`; events go through `listenTo`), bans the `localStorage` and `sessionStorage` globals outside `web/src/shared/storage.ts`, and makes `react-hooks/exhaustive-deps` an error. A disable comment for that rule is still possible and is checked in review.
  - ESLint has the HTML-sink rule (`dangerouslySetInnerHTML`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`) in `web/eslint.config.js`.
  - CI runs `cargo deny check` (bans, licences and sources on PRs; advisories daily and on release), `pnpm audit --prod` (daily and on release), and zizmor on PRs.
  - `tools/checks/process-builders.mjs` fails on a `Command::new` of `git` or `gh` outside the two builders: a string literal (`"git"`, `"gh.exe"`), a lookup such as `resolve("gh")`, or an identifier named `git`, `gh` or `git_*` / `gh_*`. It fails closed (an unreadable directory is an error). It runs in `node tools/check.mjs` (both tiers) and in the `rust-fmt` CI job. Only `crates/<crate>/tests/` may start Git to build fixtures; `src/**/tests` modules are scanned. Its limit: a program reached through an unrelated variable name, a shell string or a helper in another crate is invisible to a text check and is left to review.

The rest (IPC validation, file system, CSP) is checked in review.

## Git filters, hooks and the home

- Read-only Git invocations blank every `filter.<name>.clean`, `smudge` and `process` driver that the repository's own `.git/config` defines (enumerated with `git config --local`), because `add --all`, `status` and `diff` run them. The user's global filters (Git LFS) are left alone. `core.untrackedCache=false` stays in the forced configuration (the spec lists it); its cost is that Git drops the untracked-cache extension whenever it writes a repository's index.
- The empty hooks folder lives under the Oxide home (`no-hooks`, `0700`), not in the shared temporary folder.
- The home is walked and tightened once (marker `.private-v1`); `worktrees/` (checkouts that older versions made) and `tools/` are never entered, and a path that vanishes or refuses a change is logged, not fatal.

## Consequences

- A new process helper for `git` or `gh` means extending a builder, not adding a call site. Adding a file to `ALLOWED_BUILDERS` in the check needs a line here.
